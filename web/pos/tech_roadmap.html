🔍 1. Auditoría de los 9 Gaps Técnicos en el Repositorio

Filtra por área técnica y marca cada bloque conforme tu loop autónomo o equipo lo complete.

Backend & Persistencia P0 • Bloqueante

B1. Persistencia SQL para Créditos RBF y Pagos EMV

pkg/rbf/engine.go • pkg/payments/emv.go • migrations/
Estado Actual (Gap Detectado) SQLLedgerRepository sí guarda cuentas y pólizas en PostgreSQL, pero rbf.Engine y payments.PaymentEngine guardan los préstamos activos y cobros EMV únicamente en mapas en memoria RAM (map[string]*RBFLoan). Si el servidor se reinicia, se pierde el saldo amortizado del préstamo.
Solución a Implementar Crear migrations/002_rbf_and_payments.up.sql con las tablas rbf_loans y emv_payments, e inyectar un SQLRBFRepository con bloqueo pesimista SELECT ... FOR UPDATE durante el cálculo del Loan Sweep.
Backend & Conectores P0 • Bloqueante

B2. Clientes HTTP Productivos para PACs y STP en main.go

pkg/pac/client.go • pkg/api/server.go:61-69 • cmd/server/main.go
Estado Actual (Gap Detectado) pkg/stp/client.go ya tiene escrito HTTPSTPClient, pero NewServer() inicializa NewMockSTPClient por defecto. Asimismo, pkg/pac/client.go solo tiene MockPACClient sin el cliente REST real hacia Finkok/Facturama/SW.
Solución a Implementar Implementar HTTPPACClient (timbrado y cancelación CFDI 4.0) y conectar en BuildServer() de cmd/server/main.go la carga de llave privada RSA .pem de STP y credenciales de los 2 PACs desde variables seguras.
Backend & Resiliencia P1 • Alta Prioridad

B3. Transactional Outbox & Worker de Conciliación Nocturna

pkg/api/handlers_payments.go • pkg/stp/cep.go
Estado Actual (Gap Detectado) El cobro, el split contable y el timbrado ocurren de forma síncrona. Si un comercio vende cuando el SAT/PAC presenta intermitencia total, o si un webhook SPEI de STP llega con retraso, no hay cola de reintentos ni cuadre automático de saldos al cierre del día.
Solución a Implementar Tabla outbox_events en PostgreSQL con worker asíncrono (backoff exponencial) para timbrado diferido y descargas de CEP Banxico, más un job nocturno que compare saldos de pkg/ledger vs. STP/Adquirente.
Seguridad & Criptografía P0 • Bloqueante

S1. Integración Cloud KMS y Bloqueo de Llaves de Desarrollo

pkg/api/server.go:22 • pkg/identity/csd_vault.go
Estado Actual (Gap Detectado) server.go contiene la constante defaultVaultMasterKeyHex = "010203..." y main.go tiene un fallback softpos_dev_secret_key_12345678 para HMAC. Si se despliega así por error, los CSDs del SAT quedarían cifrados con una llave conocida.
Solución a Implementar Integrar proveedor KMSKeyWrapper (GCP KMS / AWS KMS) en csd_vault.go para cifrar la DEK, y agregar validación Fail-Fast en main.go cuando ENV=production si faltan secretos reales.
Seguridad & API P0 • Bloqueante

S2. Autenticación JWT/Passkeys, Control Tenant y mTLS en Webhooks

pkg/api/middleware.go • pkg/api/handlers_stp.go
Estado Actual (Gap Detectado) middleware.go solo incluye RecoveryMiddleware y LoggingMiddleware. Cualquier cliente puede invocar /api/v1/disbursements o consultar saldos de otro merchant_id sin token de sesión ni rate-limiting.
Solución a Implementar Añadir AuthMiddleware (JWT firmado + aislamiento estricto por merchant_id), RateLimitMiddleware sobre Redis y validación de firma + IP allowlist / mTLS en los webhooks entrantes de STP y CoDi.
Seguridad Móvil (PCI MPoC) P1 • Alta Prioridad

S3. Atestación de Integridad del Teléfono (Play Integrity / App Attest)

pkg/api/handlers_emv_codi.go • web/pos/softpos_sdk.js
Estado Actual (Gap Detectado) El endpoint /api/v1/payments/emv/authorize acepta tramas TLV sin verificar si el dispositivo móvil que originó la lectura NFC está comprometido (root, jailbreak, depurador activo o emulador).
Solución a Implementar Verificador en el backend del token criptográfico de Google Play Integrity API (Android) y Apple DeviceCheck / App Attest antes de autorizar cualquier transacción EMV.
Apps & Pos SDK P0 • Bloqueante

A1. Codificador QR ISO-18004 Real para CoDi/SPEI en softpos_sdk.js

web/pos/softpos_sdk.js:249-309
Estado Actual (Gap Detectado) La función generateQRCodeSVG() dibuja una matriz visual 25x25 usando un hash determinista FNV-1a para demostración UI, pero no contiene corrección de errores Reed-Solomon ISO/IEC 18004, por lo que la cámara de BBVA o Banorte no puede decodificarla.
Solución a Implementar Reemplazar el generador pseudo-aleatorio en softpos_sdk.js por un codificador matricial QR real (Versión 4–6 con Reed-Solomon nivel M) cero-dependencias para que cualquier app bancaria real lea el payload CoDi.
Apps Nativas (Android / iOS) P1 • Alta Prioridad

A2. Wrapper App Móvil + Puente Nativo a SDK Tap-to-Pay Certificado

web/pos/ • Android Kotlin Bridge / iOS Swift Bridge
Estado Actual (Gap Detectado) TapToPhoneService usa window.NDEFReader (Web NFC), que sirve para leer tags NDEF en Chrome Android pero no tiene acceso de bajo nivel a ISO-DEP (IsoDep APDU) requerido por Apple Pay, Google Pay y tarjetas EMV reales en iOS/Android.
Solución a Implementar Empaquetar la interfaz de web/pos/ en un shell nativo (Capacitor / Kotlin) que invoque el SDK nativo certificado (Stripe Terminal Tap-to-Pay en Fase 1 y Kushki/MineSec en Fase 2) manteniendo la misma UI y backend Go.
Apps & Portal Web P1 • Alta Prioridad

A3. Flujo UI de Onboarding KYB (Carga CSF + CSD) y Portal del Contador

web/pos/index.html • pkg/identity/csf.go • pkg/api/handlers_merchants.go
Estado Actual (Gap Detectado) El backend ya sabe parsear datos de la Constancia de Situación Fiscal (csf.go) y cifrar CSDs (csd_vault.go), pero en la UI de web/pos/index.html no existe la pantalla para que un nuevo comercio se dé de alta solo ni para exportar el reporte al contador.
Solución a Implementar Agregar en web/pos/ el asistente de Onboarding en 3 pasos (Subir CSF -> Subir .cer/.key -> Obtener CLABE STP) y el botón de descarga de pre-declaración mensual RESICO (CSV/PDF + ZIP de XMLs).
